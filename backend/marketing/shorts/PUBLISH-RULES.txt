Правила выкладки Shorts (Serpmonn)

═══════════════════════════════════════
A) Бренд и выкладка (обязательно)
═══════════════════════════════════════

1) Не делать «очень рекламными».
2) В кадре: только геймплей / момент / фейл. Без «скачай», CTA-кнопок, баннеров, офферов.
3) Название: EN | RU (+ #shorts при желании). Формула названия — свободная (не обязана быть «One more… / Almost…»).
4) Описание: коротко, вайб/геймплей. Без жёсткого призыва купить/скачать.
5) Ссылку в описании по умолчанию НЕ ставить (лучше в шапке канала). Только если явно попросили.
6) Теги: заполнять по игре (охваты), без спама в тексте описания.
7) Перед выкладкой — показать превью (файл на бэке), не заливать пачкой без ок.
8) Музыка: каждый новый Short — другой bed (не тот же games-N подряд). См. AUDIO-ROTATION.txt.

Длина ролика, конкретный стиль хука/названия, mid-run старт, дуга «давление→фейл»,
схема captions и тихий «serpmonn» в конце — НЕ бренд-обязательства. Это паттерны блока B
(можно иначе, если ролик лучше держит внимание и не ломает A).

═══════════════════════════════════════
B) Retention-паттерны (мировые Shorts)
   Цель: досмотр и повтор. Не противоречить блоку A.
   Ниже — рабочие приёмы; помеченные «опционально» можно менять.
═══════════════════════════════════════

Формат
- 9:16 (1080×1920), нативный вертикальный кадр.
- Длина: опционально ориентир ~7–12 с (апдейты иногда длиннее). Не жёсткий лимит —
  важнее плотность и досмотр, чем уложиться в секунды.
- Звук: bed/музыка ок; трендовый звук — только если не ломает тон бренда.

Хук (0–1 с)
- Первая секунда уже «что-то происходит» (движение / удар / смена состояния).
- Visual interrupt без долгого интро и туториала.
- Опционально (частый дом. приём): старт с середины забега, без меню и стояния.

Curiosity gap / open loop
- Зритель хочет досмотреть ради ответа/панчлайна.
- Опционально (частый дом. приём названий/captions): недосказанность —
  «One more…», «Almost…», «So close…». Другие формулы названия тоже ок.
- Не обязательно спойлерить или не спойлерить финал — решать по ролику.

Темп
- Плотный ритм: ускорение (setpts / cuts), без длинных пауз и zoom-punch ради шума.
- Опционально: 2–4 смысловых бита.

Дуга и payoff
- Опционально (частый приём): давление → почти → фейл / панчлайн
  (TOO FAT / caught / crash / Almost…).
- Near-miss усиливает досмотр — желательно, не обязательно в каждой формуле.
- Update-ролик: желательно в одном клипе показать новое
  (режимы / стадии / враг / механика), не «просто тот же геймплей».

Captions
- Желательно: крупный текст, читается без звука.
- Опционально (дом. схема): 2–3 коротких бита + финал + тихо «serpmonn».
- Бренд в кадре — тихо через UI/шапку игры; плашка «DOWNLOAD» запрещена (см. A2).
  Сам watermark «serpmonn» в конце — опционален.

Loopability (критично для % просмотра / докруток)
- Желательно, чтобы конец стыковался со стартом (повтор / loop).
- Финальный hold не раздувать без нужды.
- Кейс Fifteen / y8a_pPuBjD0 («One more slide…», ~7 с, avg view % ≫ 100%):
  высокий % дал не «экшен», а незаметный шов + незакрытый cliffhanger.
  Зритель не ловит момент «ролик кончился» → не свайпает → крутит дальше.
- Правило шва: последний кадр ≈ первый (тот же игровой state). Перед выкладкой
  сверить first/last (визуально или SSIM); цель — почти неотличимо.
- Cliffhanger на стыке: конец снова на «ещё 1–2 хода/клика до…», не на пустом
  Cleared/Survived/меню. Payoff (Solved) внутри ролика ок, но петля должна
  вернуть на недосбор — иначе гештальт закрывается и свайп легче.
- Старт: mid-endgame, состояние читается за ~0.5 с без меню и туториала
  (пример: пятнашки `setupTwoAway` — доска 13 · 14 15).
- Опциональная дом. дуга под loop: почти → видимый fail → тот же setup →
  правильный финиш → loopBack на cliffhanger (как record-fifteen-short /
  minesweeper). Дискретные 1–2 действия за акт читаются лучше, чем continuous
  хаос без «одного хода до…».
- Высокий avg view % ≠ охват. Сильный loop при низких views/likes значит
  «кому показали — крутят»; раздачу это само не чинит. Не путать метрики.

Эмоция
- Пик где-то в ролике (часто в конце): фейл, почти-победа, абсурдный outcome.
- Без морали и без «объяснялки».
- Мало событий в кадре не минус для loop, если шов невидимый и состояние
  «почти» читается. Плотность ради плотности шву мешает.

Чего НЕ делать (даже если «в мире так принято»)
- CTA subscribe / download / swipe-up / QR / баннеры магазина в кадре.
- Длинный cold open, голосовой туториал, «в этом видео я покажу…».
- Перегруз UI: промо-стикеры, плавающие бейджи поверх геймплея.
- Один и тот же audio-bed подряд (см. A8).
- Длинные монтажи / трейлер-каты (≈14–17 с, много склеек) — рестарт читается,
  шов ломается (анти-паттерн к Fifteen).
- Финал на Cleared/Survived/win-hold без возврата к hook-state.
- Phone crop + blur letterbox, открытие с меню.
- Стопка captions вместо 2–4 коротких битов.
- Ожидать вирусный охват только из высокого % докруток.

C) Чеклист перед превью
═══════════════════════════════════════

Обязательно (A):
[ ] Только геймплей, без CTA / баннеров / офферов
[ ] Не «очень рекламный»
[ ] Название EN | RU (формула свободная)
[ ] Описание короткое, без жёсткого download/buy
[ ] Bed не из «только что» в AUDIO-ROTATION
[ ] Превью показано → ждём ok → upload

Retention (желательно; не блокер, если осознанно иначе):
[ ] Хук в первой секунде (или читаемый cliffhanger-state с кадра 0)
[ ] Есть причина досмотреть (open loop / payoff / эмоция)
[ ] Темп плотный ИЛИ осознанный sparse + сильный шов (не «пустота без петли»)
[ ] Captions читаются без звука (если captions есть)
[ ] Hold в конце не раздут
[ ] Loop: last ≈ first (тот же state); не обрыв на чистом win/меню
[ ] Нет анти-шва: длинный монтаж / меню / letterbox blur
